Theme — enhanced organisation theme editor

Proposal for /admin/theme and Builder → Theme. Same tokens and publish rules as today; the layout inside the real app shell (app bar, breadcrumb, More rail on desktop, bottom bar on phone). Phone stacks the form above the preview. Desktop keeps the two-column grid from the shipped screen.

Aligned with todaySeven colours, corner radius, Reset to last published, Publish with validation and the contrast confirmation dialog. Preview uses the same sample list, chips, row, buttons and contrast pairs as app-theme-preview.
Grouped tokensBrand, Surfaces and Typography headings replace a single flat list. Contrast badges sit on each row while editing, not only in the list below.
Draft stateUnsaved changes and last published sit as text above the action row. Reset, Discard and Publish stay at the bottom of the form card, same as Layout and the shipped Theme screen (admin__line).
Preview surfacesTabs switch the preview between list card (default), a short form and sign-in. Only the list card is drawn in this wireframe.
Quick startOptional palettes set all colours at once; the administrator can still edit each token. Not a separate theme file.
Accessibility bannerWhen any pair is below AA for body text, a banner above the form links to the failing token. The existing dialog still appears on Publish.
Guidance copyAll user-visible strings use locale keys. Shipped keys stay unchanged; new keys are listed under Guidance copy in this file. The mockup renders the same English as packages/product/locale.

The shipped UI matches the baseline step in organisation administrator — theme: flat colour rows, preview on the right, contrast list at the bottom of the preview. This proposal keeps that structure and adds grouping, inline contrast, draft affordances and preview tabs without new server fields.

Guidance copy

Guidance is layered: field labels and live preview (always), contrast list and hint (while editing), banner and row badges (when a pair fails), field errors (invalid token), dialog (publish with low contrast), success notice (after publish). Group headings and draft affordances need new keys.

Implementation notes

  • Reuse themePairs / draftPairs for row badges and the banner; map each pair id to its token field (mutedOnSurface → muted).
  • Banner and badges use the same contrast.level.* strings as the preview list.
  • Draft detection: compare values() to themeDraft(session.defs()?.theme).
  • Add new keys to en.admin.json and the translation pipeline before UI work; Builder theme editor can reuse admin keys where both surfaces share copy.
  • Primary actions use admin__line admin__line--footer after all tokens (and optional quick start), not in the page header. Preview stays non-actionable except contrast “Fix”.
