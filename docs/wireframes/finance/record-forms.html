What changes

  1. Hint under the step button (changed). The record panel already knows which steps need approval (the approval flag in actions.ts) but does not show it. New line of text, "Needs approval by another person", with its locale key. WS1

Behaviour

  • Pressing Approve or Mark as paid opens the same form as today. After it is sent, all step buttons are disabled while the request is pending (existing).
  • The claim posts to the books only after the second person approves Pay.
  • An organisation with only one expense approver cannot move claims past Submitted. The Modules page and the setup guide should say two people must hold the role.

What changes

  1. Account lists (changed). "Paid from" on expense claims, "Received in" on earnings, "Received in" on membership fees, and a new "Received in" on donations are filled from the organisation's active money accounts. The stored value is the ledger code (BANK, BANK_HDFC, CASH), so existing records stay valid. WS2
  2. Reason field (new). Appears on the expense claim once approved, and is read by the posting rule. A server message pointing at the field shows it in place. WS3
  3. Two checks, not one (needs a plan change). The books are only written when the second person approves, but the reason must be asked of the requester. So the server must check the balance when the request is sent, as well as when it is applied, using the reason that travels with the request. Without the early check, the approver's decision would fail with nowhere to enter a reason and the request would go stale.

Behaviour

  • The list shows account names only, with no balances, so people without money:accounts:read can still pick one.
  • If no account is active for a form, the list is empty and the message says to open one on the Money page.
  • An old record whose account has since been closed shows its stored value and cannot be saved until another account is chosen.
