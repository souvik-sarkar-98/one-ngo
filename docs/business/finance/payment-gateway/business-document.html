Payment gateway set-up

Domain: finance · Entity: payment gateway

Implementation-independent · reconciled against backend (no screen yet)

1. Purpose

An organisation can take online payments through a payment gateway (Razorpay or Cashfree) in addition to direct UPI payments into its own account. Before a gateway can be used, the organisation stores its own account details with that gateway: the public key and the secrets used to create payment orders and to prove that payment notifications really come from the gateway. Each organisation uses its own gateway account; the platform never shares one between organisations.

2. Actors

  • Payment administrator (with the payment-configuration permission) — saves or replaces an organisation's gateway details and sees which gateways are set up. Every save is recorded in the audit log with who made it.
  • Finance staff — create payment requests that use a set-up gateway.
  • Payment gateway — sends payment notifications, which the organisation accepts only when they are signed with the organisation's stored secret.

3. Domain model

ConceptBusiness meaning
GatewayAn external payment service the organisation has an account with. Two are supported: Razorpay and Cashfree.
Key IDThe gateway account's public identifier (for Cashfree, the client ID). Safe to show.
Key secretThe gateway account's private key, used to create payment orders. For Cashfree it also signs payment notifications. Never shown after it is saved.
Notification secretThe secret a gateway uses to sign payment notifications (Razorpay's webhook secret). Never shown after it is saved.
EnvironmentCashfree only: sandbox for test payments, production for real payments. Sandbox unless chosen otherwise.
Gateway summaryWhat the organisation can see about each gateway: whether it is set up, whether it is enabled, its key ID and, for Cashfree, its environment.

4. Business rules

  • Only people with the payment-configuration permission may save gateway details or see the gateway summary.
  • Saving details for a gateway replaces any details saved before and enables that gateway for the organisation.
  • Secrets are stored encrypted and are never returned to anyone, including administrators. The summary only says whether a gateway is set up.
  • The summary always lists both gateways; one that has never been saved shows as not set up and not enabled.
  • A payment request through a gateway is refused when that gateway is not set up and enabled for the organisation.
  • A payment notification is accepted only when its signature matches the organisation's stored secret; otherwise it is rejected and nothing changes.
  • Cashfree payments go to the test environment unless the organisation chose production.
  • Gateways other than Razorpay and Cashfree cannot be set up.

5. User flows

Find / view

A payment administrator asks for the gateway summary and sees, for Razorpay and Cashfree, whether each is set up and enabled, its key ID and Cashfree's environment.

Create / update

A payment administrator enters the gateway's details and saves. The details replace any earlier ones, the gateway becomes enabled, and the save is audited.

Other actions

Once set up, finance staff can create payment requests through the gateway, and the gateway's payment notifications confirm those payments.

7. Out of scope / non-goals

  • A screen to set up gateways; today it is done by an administrator through the platform's interface for integrations.
  • Disabling a gateway without replacing its details, or deleting them.
  • Gateways other than Razorpay and Cashfree.
  • Showing or exporting stored secrets.
