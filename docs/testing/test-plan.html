How to read this

Smoke comes from the release gate in the functional test plan. A failing P0 smoke scenario stops the release candidate. Regression is every other scenario in that plan, including P2. On a release candidate, run smoke first, then every P0 and P1 scenario. Close and suspend scenarios need a disposable organisation.

269 scenarios sit on a single-sitting flow. The badge on a scenario names that flow. Role matrix checks prove that visibility follows the permission the organisation last published: turn it off and the destination, field, or action disappears on the next request, then turn it back on and it returns. Choosing a flow lists its scenarios in the order to run them. The other 482 need a different person, organisation, or harness, so they stay in their area.

Source: functional test plan, section 34, and the manual test plan where a scenario cites an MT id. Local app http://localhost:4200, API http://localhost:8080. Personas and the Riverbank request are in the functional plan, section 7.

No smoke scenario: Settings, Runtime engines, Privacy: consent and erasure, Languages, PWA and offline, Security behaviour visible to a tester, Accessibility behaviour, Platform operations, Guide app, End-to-end journeys, Exploratory charters, Passkeys.
