Low-level design · no vendor modules

Connector runtime

One HTTPS caller and one OAuth credential store. Slack, OneSignal, an IFSC lookup, Gmail, Calendar and Drive are saved configuration. Money, sign-in and files stay in the engines that already own them.

1. Shape

The product gains two connector types, http and oauth, on the table that already exists. Callers never open a socket. They name a connector key and a binding. The runtime renders the request, calls HTTPS, and either queues a delivery or writes mapped fields back onto the record.

Existing kinds sms, whatsapp and webhook keep working. New customer integrations use http. SMS and WhatsApp can later be stored as http templates; that move is separate from this design.

2. Two modes

send

After the record commits. An outbox event connector.http is delivered by the dispatcher, retried up to five times, and logged. A failed Slack call does not undo the donation.

Used by automations, script connector.call, and notifications.

lookup

During the save, before the write. The HTTP call happens outside the database transaction so a slow bank API does not hold a connection. Mapped fields are then written in the save, with the usual version check. A non-success answer refuses the save.

Used by the IFSC lookup and any other "fill these fields from this API" step.

A lookup connector cannot be used as a send, and the reverse. The mode is part of the saved config. An automation that names the wrong mode is a configuration error, not a runtime guess.

3. Send path

Same outbox the product already uses for connector.webhook. The event name becomes connector.http. The body is a binding, not a finished HTTP request. The dispatcher is the only component that decrypts secrets.

Save transaction
1. Caller enqueuesAutomation, script effect, or notification writes outbox_event type connector.http in the same transaction as the record. Payload: connector key, event name, record id, binding object. No secret, no rendered URL.
Dispatcher
2. LoadClaim the event. Load connector where type = 'http' and enabled. If the config names a credential, load that oauth row and refresh the access token when it is inside a minute of expiry.
3. RenderPlanner fills the URL, headers and body. Unknown placeholder, non-HTTPS URL, or a private address stops the attempt and marks the delivery failed on the last try.
4. CallconnectorHttp. Timeout from config, default 8 seconds. Redirects are not followed.
5. LogInsert or update connector_delivery on outbox_event_id. Status sent on 2xx, else pending until the fifth attempt, then failed. Response body kept to 300 characters, with secret values stripped.

4. Lookup path

The HTTP call is not inside withTenant. The write that follows uses the record's expectedVersion, so a concurrent edit is rejected instead of being overwritten with a stale lookup.

Before the write
1. Definition says which connectorA field group or a before-save hook lists { connector, inputs }. Inputs are record fields the template may read. Anything else is absent from the binding.
2. Call with no row lockRender and call. Cap the wait at the config timeout. Parse JSON only when content-type is JSON and the status is in success.
3. MapresponseMap is { recordField: "JSON.path" }. Missing path, non-scalar value, or a value that fails the field's own validation becomes a field error. Nothing is written yet.
Save transaction
4. Merge and commitCopy mapped values onto record.data and continue the normal save. Version mismatch rolls the save back; the caller may repeat the lookup once.
5. Failure logA refused lookup is the save error the user sees. A short separate transaction writes connector_delivery status failed so the attempt survives the rollback. outbox_event_id stays null. These rows are not retried; the user saves again.

5. OAuth credential

An oauth connector does not send a business payload. An http connector names it in config.credential. The product owns the callback URL. The customer supplies client id, client secret, scopes, and the provider's authorize and token addresses.

Connect, once
1. Administrator startsPOST /api/admin/connectors/:key/oauth/start with permission admin:connectors returns { url }. Insert a single-use state row: state hash, tenant, connector key, PKCE code verifier, expiry of 10 minutes.
2. BrowserRedirect to authorizationUrl with client id, redirect URI {PUBLIC_BASE_URL}/api/connectors/oauth/callback, scopes, the PKCE code challenge, access_type=offline, and the state.
3. CallbackPublic GET /api/connectors/oauth/callback (no session; the state identifies the organisation). Check state, exchange the code at tokenUrl, use the state up, and redirect to /admin/connectors/:key?connected=1 or ?error=. Encrypt { clientSecret, refreshToken, accessToken, accessTokenExpiresAt } into connector.secret_enc. Audit connector.saved.
On each send or lookup
4. Refresh under a lockSELECT … FOR UPDATE on that connector row. If the access token expires within 60 seconds, POST the refresh token, write the new ciphertext, commit, then release the lock before the business HTTP call. Two workers cannot refresh the same token at once.
5. UseThe planner substitutes {{credential.accessToken}} into the header the template declared, usually Authorization: Bearer …. The token is never written to connector_delivery or the audit after payload.

Refresh failure marks the credential enabled = false is the wrong lever: the HTTP connector stays enabled and the delivery fails with "credential needs reconnect". The administrator repeats Connect. Scopes are whatever was granted; a later save cannot silently add scopes without a new consent.

6. Data

No new database. The check on connector.type grows by two values. Credential link and HTTP shape live in config jsonb, which is already how sms and webhook are stored. Secrets stay in secret_enc.

alter table connector drop constraint connector_type_check;
alter table connector add constraint connector_type_check
  check (type in (
    'smtp','razorpay','cashfree','webhook','oidc','sms','whatsapp',
    'http','oauth'
  ));

create table connector_oauth_state (
  state_hash text primary key,
  tenant_id uuid not null references tenant(id),
  connector_key text not null,
  expires_at timestamptz not null,
  foreign key (tenant_id, connector_key) references connector(tenant_id, key)
);

connector_oauth_state is tenant-scoped with the same RLS policy as connector. Rows older than a day are deleted by the existing retention sweep.

7. Binding

The caller passes a binding. The template may only read names that are in it. An empty substitution is allowed for an optional record field. An unknown name, or a missing secret, refuses the call.

PlaceholderComes fromEncoding
{{record.<field>}}Allow-listed fields on the saved recordURL-encoded in the URL, JSON-string-escaped in a JSON body, CRLF stripped in a header
{{message.to}} {{message.title}} {{message.text}}Notification channel onlySame rules. Text capped at 1600 characters
{{secrets.<name>}}secret_enc of this connectorPlaced in the request, then redacted from logs
{{credential.accessToken}}Named oauth connector, after refreshHeader or body. Never logged
{{organisation.name}}Tenant rowSame encoding rules

Definitions name the connector in the same way scripts already declare effects.allow. A published automation or script that calls a connector key the organisation has not saved fails closed at publish time when the connector is missing, and at run time when it is disabled.

11. Rules the caller must keep

RuleWhere it is enforced
HTTPS only. No redirect. No private or link-local address.Existing connectorHttp, used by both modes.
Secrets encrypted with ENCRYPTION_KEY. API returns names, never values.Existing secret box. Audit after lists names only.
Placeholder that is not in the binding refuses the call.Planner, before any socket.
Lookup does not hold a pooled connection during the HTTP wait.Record save: call, then open the write.
Send never rolls back the business transaction.Outbox after commit. Retry updates one connector_delivery row.
OAuth refresh is serialized per credential.FOR UPDATE on the oauth row, released before the business call.
A script cannot perform a lookup.connector.call accepts send mode only. Lookups are declared on the record type.
Disabled or unfinished connector sends nothing.Same rule as today: delivery row "Not sent: the connector is not enabled."

This design does not add a plugin host, a second sandbox, or a package per vendor. The only code is the runtime in sections 3 to 5. Each customer integration after that is a connector row.
