Service sandbox

Local stand-ins for the outside services OneNGO calls. Each capability below names the production system it replaces, what the stand-in does, and how to connect it to the NGO app or the operator console.

For local development and tests only

Every service answers on this machine with fixed demo credentials. Nothing here talks to a real Razorpay, Cashfree, Google, Cloud Storage, or Have I Been Pwned account.

How it fits

Your servers call the sandbox instead of the real services. You choose which ones by putting its address into .env or into a setting saved in the app. Anything you leave empty keeps the real service.

Start it

npm run dev from the repository root starts the sandbox on HTTPS 8095, waits until it answers, then starts the API, the web app, and the operator console. Pass --no-sandbox to leave the sandbox off, or --no-console to leave the console off. The sandbox only listens. It does not write .env and it does not fill API or console variables. Prepare the database once with npm run dev:setup. The examples on this page use the default ports. Files stay in .data/service-sandbox.

To run the sandbox alone, use npm run demo:integrations from the repository root, or npm run dev in apps/service-sandbox/server. Pass --https-port to change its port. From the repository root, pass --sandbox-port; that start script forwards it as --https-port.

GET https://127.0.0.1:8095/ returns JSON links to /swagger and /openapi.json. /swagger is the API reference. GET /inbox lists accepted mail as JSON, and GET /inbox/<id> returns one message. GET /api/log returns the log, orders, and message headers. The browser warns about the certificate once on the sign-in page. Set NODE_EXTRA_CA_CERTS to the absolute path of .data/service-sandbox/tls/ca.crt before the API calls the sandbox.

Capability details

Open a capability to see which production system it stands in for, what it does, and how to connect it. Copy the values you want from the .env section. Empty values keep the real service. Nothing in npm run dev fills them.

Google sign-inSign-inSave in app

Production system

Google OpenID Connect at https://accounts.google.com, the default member sign-in issuer when OIDC_ISSUER is empty. Any other OpenID Connect issuer set as OIDC_ISSUER works the same way.

What it does

Stands in for that issuer on the sandbox origin. It serves discovery at /.well-known/openid-configuration, the sign-in page at /oauth2/authorize, the code exchange at /oauth2/token, and the signing keys at /oauth2/jwks. The sign-in page asks only for an email. The ID token marks that email verified, and its subject is demo- plus the first 20 hex characters of the SHA-256 of the lower-cased email. An authorization code lasts 5 minutes and the ID token lasts 1 hour. The sandbox does not create a member.

How to integrate it

Set these in .env, then restart the API.

VariableValueNotes
OIDC_ISSUERhttps://127.0.0.1:8095Sandbox issuer. Empty means Google.
OIDC_CLIENT_IDdemo-google
OIDC_CLIENT_SECRETdemo-google-secret
OIDC_PROVIDER_IDgoogle
OIDC_PROVIDER_LABELGoogle
NODE_EXTRA_CA_CERTSAbsolute path to .data/service-sandbox/tls/ca.crtLets the API trust the sandbox certificate.

In the operator console, open the organisation's sign-in settings and turn on the shared Google provider for that organisation. Then open the organisation sign-in page in the NGO app and choose Google.

On the sandbox page, enter the email of a member who already exists in that organisation. one-ngo refuses an email it does not already have.

Operator sign-inSign-in.env

Production system

The operator console's identity provider. Production uses an external provider that can prove multi-factor sign-in, and Auth0 is the one named for that role. Google used on its own is not accepted for operators. OPERATOR_OIDC_ISSUER holds the provider's address. Leave it empty until you choose a provider, including this sandbox.

What it does

Uses the same OpenID Connect endpoints as Google sign-in, with a second client: id and audience demo-operator, secret demo-operator-secret. The ID token includes amr values of pwd and mfa, which the operator console requires. The page does not ask for a password or a second factor; it writes those claims itself. The console still decides what the person may do, so a token for an email that was never linked does not create a session.

How to integrate it

Set these in .env, then restart the operator console.

VariableValueNotes
OPERATOR_OIDC_ISSUERhttps://127.0.0.1:8095Sandbox issuer
OPERATOR_OIDC_CLIENT_IDdemo-operator
OPERATOR_OIDC_CLIENT_SECRETdemo-operator-secret
OPERATOR_OIDC_AUDIENCEdemo-operatorSame as the client id
NODE_EXTRA_CA_CERTSAbsolute path to .data/service-sandbox/tls/ca.crtLets the console trust the sandbox certificate.

npm run dev:setup links one account, display name "Local operator", to operator.full@onengo.local on the sandbox issuer at port 8095 and grants every console action. To use a real provider, set that provider in .env and link a real subject. The console keeps OPERATOR_OIDC_MFA_ACR and OPERATOR_IAP_AUDIENCE when you set them.

Open http://localhost:9090, then enter operator.full@onengo.local on the sandbox page. A different email produces a different subject, and the console finds no account for it.

RazorpayPaymentsSave in app

Production system

The Razorpay Orders API at https://api.razorpay.com. Production calls that host. RAZORPAY_API_BASE replaces it with the sandbox.

What it does

Stands in for order creation at POST /v1/orders. It accepts HTTP basic auth with key id rzp_test_demo and key secret demo-key-secret, requires an amount of at least 100 paise and the currency INR, and rejects any other key. Orders are kept in memory; restarting the sandbox clears them. GET /api/log lists them. POST /orders/razorpay/<orderId>/capture posts a payment.captured webhook and POST /orders/razorpay/<orderId>/fail posts payment.failed. Both are signed with demo-webhook-secret. The body is JSON {"org":"demo"}.

How to integrate it

Set these in .env, then restart the API. Leave RAZORPAY_API_BASE empty to call Razorpay.

VariableValueNotes
RAZORPAY_API_BASEhttps://127.0.0.1:8095Sandbox Orders API
NODE_EXTRA_CA_CERTSAbsolute path to .data/service-sandbox/tls/ca.crtLets the API trust the sandbox certificate.

Then, as a member who can manage payment gateways such as a treasurer, save the gateway with PUT /api/admin/payment-gateways/razorpay:

{ "keyId": "rzp_test_demo", "keySecret": "demo-key-secret", "webhookSecret": "demo-webhook-secret" }

Start a payment in the NGO app. The order appears in GET /api/log with its amount and reference. Post capture or fail with the organisation key that owns the payment, such as demo or harbour. The sandbox posts to http://localhost:<backend port>/webhooks/payments/razorpay/<org> and returns JSON with the order status and the webhook answer. The order status changes only when one-ngo answers with a success status.

CashfreePaymentsSave in app

Production system

Cashfree at https://sandbox.cashfree.com when the saved environment is sandbox, which is the default, and https://api.cashfree.com when it is production. CASHFREE_API_BASE replaces both hosts with the sandbox.

What it does

Stands in for order creation at POST /pg/orders. Requests must carry x-client-id: cf_demo, x-client-secret: demo-cf-secret, and an x-api-version header, and the amount must be at least 1 rupee in INR. POST /orders/cashfree/<orderId>/capture and /fail post a webhook signed with the client secret. The body is JSON {"org":"demo"}. The order status changes only when one-ngo answers with a success status.

How to integrate it

Set these in .env, then restart the API. Leave CASHFREE_API_BASE empty to call Cashfree.

VariableValueNotes
CASHFREE_API_BASEhttps://127.0.0.1:8095Sandbox replaces both Cashfree hosts
NODE_EXTRA_CA_CERTSAbsolute path to .data/service-sandbox/tls/ca.crtLets the API trust the sandbox certificate.

Save the gateway with PUT /api/admin/payment-gateways/cashfree:

{ "keyId": "cf_demo", "keySecret": "demo-cf-secret", "environment": "sandbox" }

Start a payment in the NGO app, then post capture or fail. The webhook goes to http://localhost:<backend port>/webhooks/payments/cashfree/<org>. The JSON response and GET /api/log record the answer or a connection error.

EmailMessagingSave in app

Production system

Gmail's send method, POST https://gmail.googleapis.com/gmail/v1/users/me/messages/send. The body is {"raw":"<base64url RFC 822>"} and the header is Authorization: Bearer plus an access token. one-ngo sends that through the organisation's email connector chosen in Settings. This stand-in uses a bearer secret in place of a Google account, so you can save it without leaving the machine. There is no SMTP listener. Leave SMTP_* unset.

What it does

POST /gmail/v1/users/me/messages/send accepts that Gmail body. The request must send Authorization: Bearer demo-mail-token, and a wrong token or a raw value that is not a message is refused. The answer is {"id","threadId","labelIds":["SENT"]}. Each message is kept in memory, up to 200. GET /inbox lists them as JSON and GET /inbox/<id> returns one message, including its HTML. GET /mail/<id> returns the raw source. Restarting the sandbox clears the mailbox.

How to integrate it

Set these in .env, then restart the API.

VariableValueNotes
CONNECTOR_ALLOWED_HOSTS127.0.0.1Add to any existing hosts, comma separated. The API refuses this address without it.
NODE_EXTRA_CA_CERTSAbsolute path to .data/service-sandbox/tls/ca.crtLets the API trust the sandbox certificate.
SMTP_HOSTLeave unsetMail goes only through the gmail connector.

In Administration → Connectors, create key gmail and save this definition. Then in Administration → Organisation → Settings, choose gmail as the mail connector and set the From address to demo@localhost. That writes the organisation settings mail.connector and mail.from.

{
  "kind": "email",
  "enabled": true,
  "config": {
    "provider": "http",
    "method": "POST",
    "url": "https://127.0.0.1:8095/gmail/v1/users/me/messages/send",
    "headers": { "Authorization": "Bearer {{secrets.accessToken}}" },
    "body": "{\"raw\":\"{{ message.mime | base64url }}\"}",
    "contentType": "json"
  },
  "secrets": { "accessToken": "demo-mail-token" }
}

Send mail from the NGO app, such as an invitation or a password reset, then GET https://127.0.0.1:8095/inbox. GET /inbox/<id> returns the text and HTML. Nothing reaches a real inbox.

SMSConnectorsSave in app

Production system

The HTTPS SMS gateway saved on the organisation's sms connector. one-ngo does not call a named SMS vendor, so the connector URL is the production system. When you leave the sandbox, point that URL at the real gateway; the same {{to}} and {{message}} placeholders apply.

What it does

POST /sms accepts a JSON body and returns a queued id such as sms_…. The request must send Authorization: Bearer demo-sms-key, and a wrong key is refused. Every send is written to the sandbox log.

How to integrate it

Set these in .env, then restart the API.

VariableValueNotes
CONNECTOR_ALLOWED_HOSTS127.0.0.1Add to any existing hosts, comma separated. The API refuses this address without it.
NODE_EXTRA_CA_CERTSAbsolute path to .data/service-sandbox/tls/ca.crtLets the API trust the sandbox certificate.

In the NGO app, open Administration → Connectors, create a connector with key sms, and save this definition:

{
  "kind": "sms",
  "enabled": true,
  "config": {
    "url": "https://127.0.0.1:8095/sms",
    "method": "POST",
    "headers": { "Authorization": "Bearer {{secrets.apiKey}}" },
    "body": "{\"to\":\"{{to}}\",\"message\":\"{{message}}\"}",
    "contentType": "json"
  },
  "secrets": { "apiKey": "demo-sms-key" }
}

Use that connector from the feature that sends SMS. The sandbox log shows the body it received.

WebhookConnectorsSave in app

Production system

The HTTPS receiver the organisation names on a webhook connector. That is the customer's own endpoint, or any service that checks x-ngo-signature. one-ngo signs the raw body with the connector's signing secret, and the sandbox checks that same signature.

What it does

POST /hooks/in receives outbound webhooks from one-ngo. It reads the header x-ngo-signature, which must be sha256= followed by the HMAC-SHA256 of the raw body with demo-signing-secret. A match returns success and any other signature is refused. Both outcomes are written to the sandbox log, along with the event name.

How to integrate it

Set these in .env, then restart the API.

VariableValueNotes
CONNECTOR_ALLOWED_HOSTS127.0.0.1Add to any existing hosts, comma separated. The API refuses this address without it.
NODE_EXTRA_CA_CERTSAbsolute path to .data/service-sandbox/tls/ca.crtLets the API trust the sandbox certificate.

In Administration → Connectors, create key webhook and save this definition:

{
  "kind": "webhook",
  "enabled": true,
  "config": { "url": "https://127.0.0.1:8095/hooks/in" },
  "secrets": { "signingSecret": "demo-signing-secret" }
}

Trigger the event in the NGO app that calls this connector, then check the sandbox log.

Pincode lookupConnectorsSave in app

Production system

An HTTPS lookup the organisation saves on an http connector in lookup mode. one-ngo does not call a postal service itself, so the connector URL is the production system. This stand-in answers four India PIN codes so a record can fill its area and district. A production lookup, such as a bank or postal API, fills its own fields from its own address.

What it does

GET /lookup/<pincode> returns {"data":{"code","name","district","state"}} for the four PIN codes below. Any other PIN code returns 404.

PIN codeAreaDistrictState
110001Connaught PlaceNew DelhiDelhi
400001FortMumbaiMaharashtra

How to integrate it

Set these in .env, then restart the API.

VariableValueNotes
CONNECTOR_ALLOWED_HOSTS127.0.0.1Add to any existing hosts, comma separated. The API refuses this address without it.
NODE_EXTRA_CA_CERTSAbsolute path to .data/service-sandbox/tls/ca.crtLets the API trust the sandbox certificate.

In Administration → Connectors, create key pincode and save this definition. The response map copies data.name to area and data.district to district.

{
  "kind": "http",
  "enabled": true,
  "config": {
    "mode": "lookup",
    "method": "GET",
    "url": "https://127.0.0.1:8095/lookup/{{record.pincode}}",
    "inputs": ["pincode"],
    "responseMap": { "area": "data.name", "district": "data.district" }
  }
}

On a record that uses this lookup, enter one of the PIN codes above. A code outside the table comes back as not found.

Connector OAuthConnectorsSave in app

Production system

The OAuth authorization-code provider named on an oauth connector, with that connector's authorizationUrl and tokenUrl. For Google those are https://accounts.google.com/o/oauth2/v2/auth and https://oauth2.googleapis.com/token. The sandbox consent page stands in for that provider.

What it does

/connector-oauth/authorize shows Allow and Deny for scope demo.read, with client id demo-connector and secret demo-connector-secret. /connector-oauth/token exchanges the code, or a refresh token, for an access token. A code lasts 5 minutes and an access token lasts 1 hour. Deny returns access_denied and no token.

How to integrate it

Set these in .env, then restart the API.

VariableValueNotes
CONNECTOR_ALLOWED_HOSTS127.0.0.1Add to any existing hosts, comma separated. The API refuses this address without it.
NODE_EXTRA_CA_CERTSAbsolute path to .data/service-sandbox/tls/ca.crtLets the API trust the sandbox certificate.

In Administration → Connectors, create key demoOauth and save this definition:

{
  "kind": "oauth",
  "enabled": true,
  "config": {
    "authorizationUrl": "https://127.0.0.1:8095/connector-oauth/authorize",
    "tokenUrl": "https://127.0.0.1:8095/connector-oauth/token",
    "clientId": "demo-connector",
    "scopes": ["demo.read"]
  },
  "secrets": { "clientSecret": "demo-connector-secret" }
}

Start the connector's connect action in the NGO app. On the sandbox consent page, click Allow.

Cloud StorageFiles.env

Production system

The Google Cloud Storage JSON API at storage.googleapis.com. one-ngo calls that host. A bucket in .env talks to Cloud Storage, including the audit archive when AUDIT_ARCHIVE_BUCKET is set.

What it does

Stands in for that API for upload, metadata, download, and delete when a client calls this sandbox directly. Objects are stored as files under .data/service-sandbox/files/<bucket>/ and survive a restart. Calls must send the bearer token demo-gcs-token, which the metadata token endpoint hands out.

How to integrate it

Organisation uploads use the storage connector chosen in Settings. Point an S3 connector's endpoint at https://127.0.0.1:8095 to keep those files here. The stand-in also accepts Google Drive file calls, and the Cloud Storage JSON API when a client calls this sandbox directly. AUDIT_ARCHIVE_BUCKET is still the operator audit archive on Cloud Storage. one-ngo does not send storage.googleapis.com here.

Metadata tokenFilesReady

Production system

The Compute Engine metadata server at metadata.google.internal, path /computeMetadata/v1/instance/service-accounts/default/token. On App Engine or Compute Engine, production receives a real token from that host. one-ngo does not send that request here.

What it does

GET /token with the header Metadata-Flavor: Google returns {"access_token":"demo-gcs-token","expires_in":3599,"token_type":"Bearer"}. A request without the header is refused.

How to integrate it

Nothing to save in the app. Call GET /token on the sandbox directly. one-ngo does not send its metadata token request here.

Breached passwordsSecurityReady

Production system

Have I Been Pwned's Pwned Passwords range API at https://api.pwnedpasswords.com/range/<5 hex characters>. With the check left on and PWNED_PASSWORDS_API_BASE empty, one-ngo calls Have I Been Pwned. That base replaces the host.

What it does

GET /range/<5 hex characters> answers in the same SUFFIX:COUNT line format. Only the exact word password is reported breached, and every other password is reported clear.

How to integrate it

Set this in .env, then restart the API.

VariableValueNotes
BREACHED_PASSWORD_CHECKonline (default) or offonline calls the range API. off skips the check.
PWNED_PASSWORDS_API_BASEhttps://127.0.0.1:8095Empty keeps Have I Been Pwned. Set NODE_EXTRA_CA_CERTS so the API trusts this certificate.

GET /range/<prefix> on the sandbox is the local stand-in for tests that call it directly. The word password is the only value that stand-in reports as breached.

Copy a row into .env only for the stand-in you want, then restart the API or the console. Leave a key empty to keep the real service. The same comments are in .env.example.

Troubleshooting

ProblemWhat to do
Certificate warning in the browserAccept it once on the sign-in page. Set NODE_EXTRA_CA_CERTS to the absolute path of .data/service-sandbox/tls/ca.crt so the API trusts the same certificate.
Port already in useStop the process using that port, or pass another one. The sandbox takes --https-port. The API, web app, and console take --port.
Mail never appears in the inboxSave the gmail connector, switch it on, and choose it under Settings with From demo@localhost (mail.connector and mail.from). Leave SMTP_* unset.
Operator sign-in creates no sessionEnter operator.full@onengo.local. A different email does not match the one account npm run dev:setup linked.
Sign-in, payments, or the password check still call the real serviceSet that service's URL in .env and restart. Empty OIDC_ISSUER means Google. Empty payment bases mean Razorpay and Cashfree. Empty PWNED_PASSWORDS_API_BASE means Have I Been Pwned. Organisation files wait until Settings names a storage connector.
Start from clean dataStop the sandbox and delete .data/service-sandbox. The next start creates new certificates and files. Mail and orders were only in memory.

Keep the organisation's saved credentials and the sandbox values in step. If you change a secret in one place, change it in the other.
