Report builder — custom PDF and Excel reports

An administrator builds a report the way they build any other definition: in the Builder, on the shared editor frame (Visual, JSON, Changes, History tabs, with Discard, Check and Publish). A report gathers data from one or more record types, adds calculated values and, if needed, custom code, then produces a PDF from an HTML document template and an Excel workbook from the same data. Tablet and desktop only, like the other editors.

One data model, two outputsParameters, datasets, calculations and the optional shape step produce one data model. The PDF template and the Excel sheets both read it, so the numbers always match.
The person's own accessDatasets run as the person running the report. Records they cannot see are left out, and sensitive fields stay masked in both the PDF and the Excel file.
HTML like email templatesDocument templates use the same {{ placeholders }} as email, plus {{#each}}, {{#if}} and {{> partial}}. Scripts, event handlers and remote addresses are removed.
Custom code is guardedThe shape script runs in the existing sandbox with time and size limits, proposes no changes, and only an organisation administrator can publish a report that uses one or reads ledger balances.
Editor layoutThe report editor adds one row of section chips under the frame tabs: General, Parameters, Datasets, Calculations, Outputs and Preview. A strip above them shows the flow, parameters → datasets → calculations → shape → PDF and Excel, with the current section highlighted and a count or warning on each step.
