User guide screen

The guide is drawn inside the organisation app, so it has no bar of its own. It reads a compiled list of steps, draws one product screen, and outlines the control for that step in yellow. Back and next sit beside that picture. Web and Mobile sit on that screen.

One list, no APISteps live in the guide catalogue. Opening the guide does not load an organisation’s record types, workflows, or pages.
Web or Mobile, on the screenEach screen has its own switch. Mobile is the phone: cards and a bottom bar. Web is the browser: a table and a side rail.
Yellow outlineEach step names one control. That control gets a 3px outline, #f3be26, the same mark as the navigation wireframes.

Flow

How a step is loaded

Nothing is fetched at open. The catalogue is already inside the built guide. The address only chooses which step to draw.

Build

Cataloguecatalogue.ts exports GUIDE: sections, chapters, and steps. A step has the instruction, the product address, the phone and desktop notes, the screen, and the control to outline.
Guide buildThe list is compiled into dist/guide/browser. There is no definition request at runtime.

Host

OneNGO serverServes that build at /guide-app/.
Guide pageguide-frame.ts shows /guide-app/ in a frame. The dev proxy sends that path to port 4300.

Open

Address/:section/:chapter. An unknown pair is replaced with a real chapter in that section, or with App → Sign in.

Choose the step and the frame

Step?step= must be a whole number from 1 to the chapter length. Anything else opens step 1.Previous and Next rewrite this query.
FrameWeb or Mobile is chosen on the screen, not in a guide bar. Mobile draws the phone. Web draws the browser.

Draw

PictureThe stage reads step.screen and draws the phone frame or the browser frame.
Yellow outlinestep.highlight names one control, such as nav:records, chip:All, or search.
