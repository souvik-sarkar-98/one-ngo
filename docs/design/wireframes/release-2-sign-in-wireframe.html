Use another organisation

  1. OneNGO is the product name. It is fixed, and an NGO administrator cannot edit it or replace it with their own wordmark.
  2. Helping Hands is tenant.name, the display name. The legal name stays off this screen.
  3. The logo is the NGO’s stored file, served from the same origin. The house mark above is a stand-in for that file. When no logo is stored, the slot is omitted. The screen does not invent initials and does not load a remote image.
  4. Email and password sit in the Password tab. Email code is the other tab. The organisation code is absent because the address already resolved it.
  5. Sign in with Ministry SSO sits under the tab container, outside it. The label is that NGO’s provider. It appears after the organisation has resolved, and it is omitted when that NGO has no provider.
  6. Use another organisation sits below the SSO button. It clears the remembered code in this browser and opens /sign-in.
  7. A wrong password stays on this screen. The notice is the server’s message. Reset and email-code notices still avoid saying whether the address is a member.
  8. After a successful sign-in, Home’s title is Helping Hands and the shell keeps OneNGO beside that name.

03

Code, reset, and the authenticator

Password and email code are tabs in one container. The organisation’s SSO button stays under that container on every tab. Sample NGO: Helping Hands, with its logo.

04

Set a password, then return here

The first administrator, and anyone who resets, still sets a password on the existing one-time page. Release 2 puts the NGO on that page and sends them back to the organisation’s sign-in. No initial password is included in the invitation.

05

Code fallback and the unavailable screen

/sign-in is no longer where someone types a password. If this browser last signed in to an active organisation, it opens that organisation’s screen immediately. Otherwise it asks for a code.

Remembered organisation

The last successful code is stored in this browser. Opening /sign-in with helpinghands remembered, and that NGO still active, goes straight to /o/helpinghands/sign-in.

If the remembered code is missing, unknown, or no longer active, it is dropped and the code form is shown. Choosing Use another organisation clears that memory only. It does not end a session on the server, because this person is not signed in yet.

07

Kept off this screen

  • Legal name, registrations, address, phone, and email of the NGO. The public lookup returns the display name and the same-origin logo of an active NGO, and it is rate-limited.
  • An organisation directory, autocomplete, or “find my NGO by email”. Email-first discovery waits for a later release.
  • A remote logo address. A missing logo leaves the name on its own.
  • A distinct sentence for suspended, closed, provisioning, or unknown. One unavailable screen covers all of them, and the tab does not reveal the display name.
  • An initial password. The invitation is a single-use set-password link, valid for seven days, sent after the organisation is created.
  • The operator’s provisioning command, the setup checklist, and receipt identity. Those are Release 2, and they are separate screens.
  • The app bar, navigation, and breadcrumb. Sign-in and set-password stay bare, as they are today.
