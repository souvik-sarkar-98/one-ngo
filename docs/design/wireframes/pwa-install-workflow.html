Install app

How a person installs one organisation as its own app, as built on develop. There is no install page. Settings installs in place. The installed app opens that organisation’s sign-in page.

WhereMore → Settings → Install app. The sign-in page does not offer it.
NameThe organisation’s display name. Each organisation is a separate installed app.
Opens/o/<code>/sign-in, in its own window.
IconThe organisation logo when one is set. The shared heart when it is not.
Known bug. On Windows, Chrome’s shortcut and taskbar still show a letter (the first letter of the name) instead of the logo. The icon file is a square PNG. Removing the app and installing it again does not replace the letter.

1. The page prepares the install

This happens on a full page load, before anyone taps Install app. The browser needs the manifest while the person is still on the site.

Address or last organisation

Find the organisation code

The inline script in index.html reads /o/<code>/…. If the path has no code, it uses ngo.lastOrganisation from local storage when that value is a sign-in code.

Same page load

Attach the organisation manifest

It adds <link rel="manifest"> pointing at /api/auth/organisations/<code>/manifest.webmanifest, and points the Apple touch icon at /api/auth/organisations/<code>/icon/180. No code means the shared heart stays in place and no organisation manifest is attached.

Startup

Wait for the browser’s install offer

watchInstall() stores beforeinstallprompt and hides the browser’s own banner. It also notices when the window is already the installed app (display-mode: standalone).

2. What the manifest tells the browser

The public manifest route builds this for an active organisation. A missing organisation is the same 404 as the sign-in lookup.

FieldValue
nameDisplay name
short_nameThe name when it is 12 characters or fewer, otherwise the code
id/o/<code>/ so two organisations do not replace each other
start_url/o/<code>/sign-in
scope/ so the signed-in app stays in the same window
displaystandalone
IconsSquare PNGs of the logo at 192, 512, and 180 when the stored logo is PNG, JPEG, or WebP. Otherwise the shared heart in /icons/. A WebP file is requested as a logo but cannot be drawn, so that install uses the heart.

3. The person installs from Settings

Install app is shown only after sign-in, and only when the session’s organisation has a sign-in code and the window is not already the installed app. The click stays on Settings.

Add this organisation to your home screen. It opens on the sign-in page.

Chrome or Edge has offered a prompt

The button calls the stored install prompt. The browser’s own dialog appears. Dismissing it does not open a second sheet.

No navigation

iPhone or iPad

There is no prompt. A sheet on Settings lists:

  1. In Safari, tap Share
  2. Tap Add to Home Screen

Any other browser

A sheet on Settings says: open the browser menu and choose Install app, or Add to Home screen.

After the person accepts

The installed app is that organisation

The shortcut is named with the display name. Opening it loads /o/<code>/sign-in. Once the window is the installed app, Settings hides Install app. An organisation with no logo uses the shared heart. An organisation with a logo is meant to use that logo.
