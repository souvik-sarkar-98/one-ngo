Builder — every screen, everything configurable

What an administrator uses to set up the organisation without code. The Builder uses the same controls as the rest of the app: chips, search, Sort, Filters, section headers, Material fields, panels, pills, the ⋮ menu. Every editor shares one frame: a Visual tab, a JSON tab, a Changes tab and a History tab, with Discard, Check and Publish. Editors are for tablet and desktop; phones see the catalogue and published settings read-only.

Draft, check, publishChanges are saved as a draft automatically. "Check" runs every validation and cross-reference check; "Publish" is enabled only when there are no errors and shows a plain-language summary first.
Module definitions stay upgradableEditing something a module ships saves only the organisation's differences as a patch. The Changes tab shows them, and "Revert to module version" removes them.
Expressions with helpEvery expression field (conditions, calculated fields, guards, amounts) has field and function suggestions, a live syntax check, and "Try it" against a sample record.
Live previewsList views, templates and the theme show a live preview on phone and desktop while editing.
First-release additions — screens 20 to 23 (approved 2026-10-24)Page editor, action editor, translations grid, and the workflows of one record type (Design §13a). Connectors and API keys are not Builder screens: they are in Administration in the app (app Journey 23). Pages and translations are hand-built editors; actions and connector settings are the generic visual editor generated from their rules, shown here with the controls it produces.
Breadcrumb (added 2026-10-24)Every Builder screen starts with the same breadcrumb as the rest of the app: Builder › kind › definition › tab or selection, for example Builder › Record types › Donation › Field: Donor name, or Builder › Workflows › Donation workflow › Step: Mark as paid. It is built from the screen's address by one helper; earlier items link back, the last is the current page. Drawn here at the top of each screen; in the app it is the shell's single breadcrumb line under the app bar, so the editor header does not repeat it.
Access and profiles — screens 24 to 27 (approved 2026-10-24)The Builder keeps only definitions. People, role assignment and the operational settings are in Administration in the app (app Journeys 21 and 23). Screen 18 defines what each role allows. Screen 24 is the Access map (what each part of the app requires and who holds it), 25 its role view ("What can Viewer see?"), 26 the permissions on fields, sections, widgets and links with the permission autocomplete, and 27 the profile record type person.
Shell chrome (updated 2026-10-25)The blue bar is the same as the rest of the app: NGOOne, the organisation name, the inbox and the account initials. It does not say "Builder" and it has no back arrow. Back sits on the same row as the screen heading (Builder, or the definition being edited).
