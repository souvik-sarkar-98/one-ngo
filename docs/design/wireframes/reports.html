Reports — the same screens as records

Reports is its own destination, beside Records. It uses the same app bar, breadcrumb, groups, list, create panel and print page. A report is one format, PDF or Excel, taken from its definition. Names and amounts on the pages are sample layout.

Groups, like RecordsOne column on every size. A section header per report group, collapsible. A report the person cannot run is left out, and an empty group is hidden. No counts.
One formatThe definition chooses PDF or Excel. The list, the preview and the download are that one file. There is no second button for the other format.
Preview adds nothingNew report opens the parameter panel, the same panel as creating a record. Preview runs the report and opens the print page. No row is added and no file is stored.
Publish keeps the filePublish writes that PDF or Excel into the file store and adds one row: parameters, who published it, and when. Download, and Preview on that row, return the stored file. Running it again publishes another file.
